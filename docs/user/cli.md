# CLI reference

Every loop action is available from the `ratchet` command, and every command calls the same
orchestrator functions the dashboard API calls. Nothing is CLI-only, and nothing in the
dashboard is missing from the CLI.

Run commands with `uv run` from the repository root. Each command reads its settings from
the environment and `.env` (see [Configuration](configuration.md)).

```bash
uv run ratchet --help
uv run ratchet <command> --help
```

!!! warning "Commands that can spend money"
    With `RATCHET_UPSTREAM=live`, these commands call Token Factory and cost money:
    `seed-demo`, `bless`, `agent run`, `agent start`, `replay`, `simulate`, `digest run`,
    `verify-live`, `bench build` and `bench run`. `seed-demo` prints its estimate first.
    `verify-live`, `bench build` and `bench run` ask for confirmation or `--yes`. Every call
    still goes through the spending caps. With `RATCHET_UPSTREAM=sim`, nothing is spent.

## Common tasks

| Goal | Command |
| --- | --- |
| Check the install | `uv run ratchet doctor` |
| Seed the demo agent and its 25 goldens | `uv run ratchet seed-demo` |
| Start everything (dashboard, proxy, mock tools, orchestrator) | `uv run ratchet serve` |
| Run a seeded scenario without the browser | `uv run ratchet simulate 1 --headless` |
| Run one task on your agent and bless it | `uv run ratchet agent run "<task>"` then `uv run ratchet bless --last` |
| See what is in flight, what was spent today and its prompt-cache share | `uv run ratchet status` |
| Stage timings of one verdict | `uv run ratchet status --timing <verdict_id>` |
| Undo an edit | `uv run ratchet rollback <verdict_id>` |
| Ship a held edit | `uv run ratchet approve <verdict_id>` |
| Accept that the world changed | `uv run ratchet rebless <golden_run_id> <replay_run_id>` |
| Delete old traces | `uv run ratchet purge --before 2026-10-01` |

## Exit codes

- `doctor` exits 1 when any check fails. Warnings don't fail it.
- `simulate` exits 0 only when the decision matches the scenario's expected decision, so you
  can use it as a smoke test (the deploy script does).
- `verify-live` exits 1 when any live check fails, or when you decline the cost prompt.
- `bench validate` exits 1 when the dataset has problems.
- Errors print `error <code>: <message>`, using the stable codes listed in the
  [error code table](api.md#error-codes).
